# 碩論方向淘汰與週二討論備忘錄

## 決策建議

9 月 15 日的個人 meeting，建議帶「兩個候選問題、一張近鄰文獻比較表、一個兩週內可推翻假設的實驗」，目標是與指導教授決定下一段投入。現在最值得深入的是：**控制模型能力與作弊機會後，有限診斷證據能否預測未見情境下的 reward-hacking 行為？** VDAR 的決策可靠性保留為備選；封閉企業模型落差暫作部署情境。

這個優先序是研究策略判斷，並非已證實的新穎性。文獻查核截至 2026-09-12；所有後述實驗都是建議設計，尚未執行。公開來源支持的是特定研究設定下的結果，不代表已有方法可以普遍診斷或修復任何模型。

選題要同時回答四件事：問題是否重要、最接近的工作做到哪裡、最簡單方法是否已足夠、即使方法被超越還留下什麼知識。無法保證一年後沒人解決，但可以讓每兩週的投入都產生可檢驗的判斷，避免一年後才發現起點不成立。

## 一、先修正原有資料中的判斷

### 1. 老師提供的是研究 seed，題目尚未承諾

老師的四頁檔案明確提出：給定訓練歷史未知的模型，診斷 reward-seeking / reward-hacking tendency，再思考能否保留正常能力而移除它。實驗室介紹也說，學生可以討論自己感興趣的主題。[1][2]

這不等於教授已同意「adaptive probing」或「selective diagnosis」；這些是後續討論產生的候選。先前貼文中的 meeting 日期、first meeting 等描述若只來自生成的整理，應維持待確認，不能升格成老師的承諾。

### 2. 老師 PDF 上的英文文字與目前連結標題不同

PDF 第 1 頁寫的是「Can We Repair a Reward-Hacked Language Model?」，目前連結頁面的標題是 **Training a Misaligned Reward Seeker**。報告時應引用目前實際文章名稱；repair 可以作為老師提出的研究問題，不要稱它為一篇已讀完的同名論文。[1][5]

### 3. 「只取平均是統計缺陷」不成立

V2 將未使用鄰居變異數直接稱為缺陷，這個說法需要撤回。若目標是最大化期望效用，且條件平均估得準，取平均本身合理。真正問題是：**估計誤差會不會使模型排序出錯，新增訊號能否改善決策？**

還有一個可直接檢查的數學問題：若每個鄰居的 performance 是二元成功／失敗、鄰居數固定，樣本變異數為

\[
s^2=\frac{k}{k-1}\bar p(1-\bar p).
\]

此時「相同平均、不同原始變異數」不可能發生；新增這種 variance 不會帶來獨立資訊。若 performance 是連續分數，或使用含成本的 reward，則需要另行分析。**必須先確認 VDAR 實際資料與公式，不能把這個條件式反駁直接當成 VDAR 的結論。** 本次取得 VDAR 摘要，但全文讀取未成功；公式細節仍需用手上的論文逐項核實。[4][14]

若要研究不確定性，較有意義的候選包括：檢索距離、局部資料密度、相似案例的相關性、難度描述變動、模型間的配對效用差。對排序而言，差值的變異数含有模型間共變異數，並非各自成功率的變異數就能完整表示。

### 4. 「大問題持續存在」不保證「我的方法持續有價值」

Reward hacking 可能在能力更強的系統中持續存在，但不能據此斷言自己的 detector 一年後仍新穎。更好的模型、訓練方法、監控方法或環境修補，都可能消除你目前測到的特定失敗。Anthropic 的研究提供特定訓練設定中的失敗證據，並未證明所有未來模型都必然如此。[5]

同理，成本函數來自部署方，並不代表模型無法使用明確提供的成本；封閉環境也不必然永遠無法更新。這些是要寫清楚的部署假設，不是題目永遠成立的保證。

## 二、Novelty kill-screen 要查什麼

「Novelty kill-screen」在這裡是工作流程名稱：刻意找足以否定題目新意的證據。它應搭配可行性與模型升級測試，而非只搜尋相同論文標題。

| 檢查 | 問題 | 能讓題目停下來的證據 |
|---|---|---|
| 文獻重疊 | 相同輸入、存取條件、輸出與評估目標是否已有方法？ | 最近方法可直接在同一設定完成核心主張 |
| 簡單解法 | 更強模型、提示、少量校準、固定 probe 是否已足夠？ | 複雜方法在同成本下沒有實質優勢 |
| 現象真實性 | 觀察到的是傾向，還是能力、格式、資料洩漏？ | 控制混淆因素後，原本效果消失 |
| 資源可行性 | 模型、標籤、程式和足夠獨立樣本拿得到嗎？ | 必要資源拿不到，替代品又無法支撐主張 |
| 升級韌性 | 換更強 target 或 auditor，效果是否仍有意義？ | 優勢只存在於過時模型或某個特殊弱點 |
| 剩餘價值 | 若方法被超越，還留下什麼？ | 只留下某版模型上小幅提升，沒有可重用評估或解釋 |

「新論文做過類似主題」不足以直接淘汰；要對齊存取權、資料、預算及決策目的。反過來，「對方沒用我的術語」也不足以宣稱新穎。實務上可問：把對方方法直接搬過來，如果已解掉我的問題，我到底新增了什麼？

## 四、三個值得拿去討論的研究問題

### A. 優先：有限行為證據能否預測未見機制的作弊？

**問題句：在明確指定的環境分布、模型存取條件與測試預算下，少量 probes 能否在控制能力後，比簡單基準更準地預測未見作弊機制上的行為？**

這裡的「傾向」應先定義為指定評估分布中的行為頻率或風險，而不是模型具有某種可直接讀出的永久人格。若連跨情境預測都做不到，直接研究如何自適應選題，很可能只是在更有效率地量測錯東西。

例如模型 A 沒作弊，可能是它不願意，也可能它不會用工具、沒看出機會、或根本沒走到可作弊節點。模型 B 作弊較多，也可能只是更有能力。School of Reward Hacks 的限制段落已指出能力降低會妨礙成功利用漏洞，這讓「能力與傾向分離」成為應先檢查的問題。[6]

**最小證偽實驗：**先用固定 probes，對公開的同基底原始模型、正常微調控制、reward-hacked 版本做比較。probe 集與最終測試集按作弊機制分開，另保留不同訓練來源或模型家族作外部檢查。先問：診斷分數在 held-out 機制上，是否比乾淨任務能力、固定隨機 probes 的作弊率更有預測力？

**關鍵 baseline：**乾淨能力分數、隨機固定 probes、依機制分層的固定 probes、同預算的通用 LLM investigator。若做自適應，加入相同 probe bank 的固定排序，避免把「題庫比較好」誤認為「選題策略比較好」。

**淘汰／縮題條件：**優勢只在相同模板隨機切分下存在；換作弊機制就崩潰；控制能力後訊號消失；或可用獨立模型太少，無法支持 model-level 泛化。此時可以縮成特定環境的診斷，不要保留普遍傾向的敘事。

### B. 次優先：修復效果是在降低作弊，還是在降低能力或可見度？

**問題句：既有 mitigation 在未見機制與不同監控條件下，是否仍降低作弊，且正常任務能力得以保留？**

先研究如何辨別修復效果，暫不承諾發明完整修復算法。對照現成 prompt mitigation、正常資料 SFT 或可取得的文獻方法，報告 clean task success、作弊嘗試、作弊成功、拒絕率、監控偵測率。只報「被抓到的作弊變少」不足以支持 repair。[7][9]

**最小證偽實驗：**同一 checkpoint 修復前後，用配對任務與 held-out 機制評估；能力變差導致 exploit 失敗要與作弊意圖／嘗試分開。若只是更常拒絕全部任務，也不能聲稱保留正常能力。

**淘汰／縮題條件：**已有工作在同樣條件和指標下完整回答；或資料只能顯示總成功率下降，無法區分機制。這條線適合與老師討論，但最容易膨脹成「偵測＋因果解釋＋修復＋泛化」四件事，要明確取一件。

### C. 備選：什麼局部證據真的能預測 VDAR 排錯模型？

**問題句：在控制平均效用與前兩名差距後，局部證據品質能否額外預測 misrouting，並在同成本下改善決策？**

先核對 performance 的資料型態。以平均效用、top-two margin、距離／密度作基準；再檢查配對效用差或難度分析穩定性。不要先加 conformal、drift、human fallback 才回頭找現象。

**最小證偽實驗：**利用既有 per-query model outcomes 做離線分析，學習／校準／測試分離。先畫新增訊號與 misrouting 的關係，再比較 VDAR 與簡單 margin threshold；要測棄權則明定停止回答或升級模型的實際動作及成本。升級模型不是零錯誤 fallback。[14][16]

**淘汰／縮題條件：**新增 variance 只是平均的函數；不優於簡單 margin；只在特定成本權重有效；或學長姐已有相同延伸且沒有合作空間。即使 LENS 不是完全同一方法，也不能據此忽略 RACER 等近鄰。

### 目前排序的理由

| 候選 | 值得投資之處 | 第一個要解開的風險 | 週二定位 |
|---|---|---|---|
| A 跨機制行為診斷 | 對到老師 seed，也保留 uncertainty／decision 興趣 | 行為分數是否超越能力與模板訊號 | 主談，爭取兩週驗證 |
| B 修復效果判別 | 與老師問題直接相關，負結果也可能有解釋價值 | 評估能否區分能力退化與真改善 | 第二問題，暫不與 A 全包 |
| C VDAR 排序可靠性 | 可能有現成資料與合作入口 | 新穎性與原始變異數假設 | 資源明確時作備選 |
| 封閉企業 capability lag | 可用作部署動機 | 太廣，更新限制與時間資料未確認 | 本次不獨立開線 |

## 五、最值得 brainstorm 的六個分岔

### 1. 診斷單一 trajectory，還是預測模型未來行為？

前者問這次有沒有作弊；後者問有限觀察能否泛化到未來情境。兩者的標籤單位、獨立樣本數和 baseline 都不同。大量 trajectories 不能取代足夠多獨立模型；同一基底模型的多個 checkpoint 也不能全部視為獨立模型家族。

### 2. 抓到一個反例，還是估計整體風險？

最容易誘發作弊的 probe，適合找反例，未必適合估計部署頻率。adaptive testing 會改變抽樣分布；不能把適應性選出的高風險題作弊比例，直接報為部署作弊率。

若目的在模型選擇，輸出可以是「在指定測試分布較高風險／證據不足／達到事先訂定的風險界限」。不要輸出無條件的 safe certificate。證據不足應是可評估結果，也要限制 abstain-all，否則所有模型都不下結論就能假裝低錯誤。

### 3. 黑箱、灰箱、白箱，哪個是合理限制？

黑箱只看互動；灰箱可能有 token probability／可見推理；白箱可讀權重與梯度。Unknown training history 不等於 black-box。能取得權重卻不知道訓練資料很合理；若刻意不用權重，應說明是可轉用閉源模型、成本或部署需求，而非為了躲 baseline。

### 4. 用什麼控制能力與機會？

設計相近任務的「漏洞不可用／可用」配對，另有乾淨能力測試，並記錄模型是否到達作弊機會。可增加明確提示存在捷徑的條件，幫助拆解「沒發現」與「發現後不用」，但這會改變情境，不能當成自然部署頻率。

Prompt 的變化也可能改變模型對允許行為的理解，因此任務規則需要清楚。能力控制本身不保證完成因果辨識，初步報告應稱為控制混淆因素的診斷設計。

### 5. 哪一種 generalization 最重要？

先選一個主軸：未見任務、未見作弊機制、未見訓練來源或未見模型家族。這四個不能混稱「OOD」。主建議是未見作弊機制，模型來源外推作後續 gate；若資源允許，再逐步擴大。

### 6. 什麼成果即使被超越還有價值？

優先累積明確標籤規則、機制切分、配對控制、可重現 baseline 和失敗案例。若證明某個常用診斷分數其實主要量到能力、或未見機制上不泛化，仍可能形成有價值的分析；但負結果要有足夠實驗與解釋，不能保證自然可發表。

## 六、兩週 pilot 的具體版本

以下是規模建議，需依公開模型清單和教授資源調整，並非統計 power 計算。

**第一階段：先驗证測量能否成立。** 用一個可取得的基底家族與其控制／作弊版本確認環境能跑，人工查看每一類標籤是否可信。模型不會工具操作時先修環境適配，不把它記成不作弊。

**第二階段：測跨機制訊號。** 理想小型設計為 6 個模型／checkpoint、4 類機制、每類 15 個情境、每情境 2 次生成、2 種配對條件，共 1,440 個 episodes。這只夠探索性篩選；多個 checkpoint 的相關性必須記錄，不能據此宣稱普遍跨模型保證。episodes 也不等於 API requests，多輪工具任務會大幅增加成本。

| 比較方法 | 最低必要性 |
|---|---|
| 只用乾淨任務能力預測 | 檢查是否只量到能力 |
| 同預算隨機 probes | 避免只因做更多測試而贏 |
| 機制分層固定 probes | 避免適應性只是在補分布覆蓋 |
| 通用 LLM investigator | 檢查更強現成模型是否已足夠 |
| 候選診斷分數 | 第一階段保持簡單可解釋 |
| Adaptive probe 選擇 | 僅在固定 probes 已有泛化訊號後加入 |

主要結果依目的選擇。做偵測時看固定 false-positive rate 下的 recall；做風險估計看 held-out calibration／Brier score；做停止策略看錯誤放行率、覆蓋率、平均與尾端成本。所有方法都要連同乾淨能力與拒絕率報告，不只列 AUROC。

模型泛化推論應以模型／訓練来源為群組；任務推論則按情境／機制群組處理不確定性。小樣本結果報原始計數與不確定性，不將「未顯著」等同「已證明沒有作用」。

**兩週後保留的條件：**資料沒有明顯洩漏、存在可重現的受控行為差異、held-out 機制有訊號、且資源可支撐擴展。若未通過，只允許一次有明確原因的修正，例如工具格式不匹配；不要無限換 prompt 到看到想要的答案。

## 八、週二報告的六頁內容

實驗室研究生需知第 6 頁建議先花 1–2 分鐘回顧、1–2 分鐘列討論事項，再進入進度討論。以下安排約 8–10 分鐘陳述，留下討論時間；個人 meeting 不必套用 seminar 的 30 分鐘導讀規格。[3]

| 頁面 | 內容 | 可以直接講的句子 |
|---|---|---|
| 1 進度與目的 | VDAR 閱讀的真實進度、老師 seed、新增近鄰；決定兩週驗證方向 | 「我這週先釐清哪個主張值得投入，整理了兩個問題和會讓我放棄它們的證據。」 |
| 2 文獻已做到哪裡 | AuditBench、TRACE／GRIFT、HackProbe；routing 用 RACER／LENS 補充 | 「未知模型診斷和 routing 棄權都有工作，所以我不會把這些詞本身當成貢獻。」 |
| 3 第一候選的關鍵歧義 | 未作弊可能來自能力不足、機會不足或行為偏好 | 「我想先確認診斷分數在控制能力後，能不能預測沒見過的作弊機制。」 |
| 4 最小比較設計 | 控制／作弊模型、配對條件、機制切分、固定 baseline | 「第一輪先不用 adaptive；固定 probe 若沒有可泛化訊號，自適應選題也缺乏基礎。」 |
| 5 生存與停損 | 強 auditor、簡單 prompt／固定題庫、held-out 機制；VDAR 備案 | 「如果控制能力後效果消失，或現成 investigator 同成本已足夠，我會縮題或換題。」 |
| 6 請老師一起決定 | 主軸、可用資源、既有合作、兩週結果門檻 | 「我想先投入兩週做這個驗證；哪些設定您覺得最能產生有研究價值的判斷？」 |

若沒有實驗數據，第 4 頁就明標「實驗設計」並放一個手工示例，不能把文獻數字當自己的 reproduction。若只有 smoke run，稱為可執行性確認，不稱初步支持研究假設。

### 開場範本

> 老師，我看了您給的行為異常方向，也重新檢查原本 routing 的想法。現在已有未知模型 auditing，以及 routing 風險控制和棄權的工作，所以我想把問題縮到：少量測試觀察到的行為，控制模型能力後，能不能預測未見作弊機制的風險？我先設計了固定 probe 的兩週驗證；如果跨機制訊號不存在，就先不投入 adaptive probing。今天想請您幫我判斷這個切法、可用模型與 baseline，以及先做哪一個小實驗。

這段只有在相關閱讀確實完成後才用「我看了」；否則改成「目前查到／正在讀」。

### 最值得問教授的五個問題

1. 在 seed 中，您比較希望研究「發現已發生的異常」還是「預測未知模型未來的行為」？
2. 實驗室是否已有 reward-hacked 模型、評估環境或正在進行相同方向的同學？
3. 這個階段黑箱互動夠合理嗎，還是有權重／梯度資源值得利用？
4. 您覺得「能力與作弊傾向混淆」值得當研究主張，還是應只當實驗控制？
5. 兩週後最有決策價值的成果，是跨機制泛化表、失敗案例分析，還是 VDAR 的 baseline reproduction？

經費討論帶 request／episode 數、預估 token、重試上限與金額，不只說「先跑看看」。需知第 11–15 頁對共用 API 大規模實驗和 H100 使用有事先討論要求；目前只規劃實驗，尚未消耗這些資源。[3]

## 九、降低未來一年白費的節奏

### 第一個月

第一週核對資源、定義和近鄰；第二週驗證固定 probe 的訊號；第三至四週加入強 baseline 與 held-out 切分。此時應能決定主張是「新方法」「某個評估混淆」「某種泛化失敗」，或停止投入。

### 第 2–3 個月

只讓一個主張進主實驗，擴展模型來源並記錄成本。把資料切分與評估規則固定，避免隨效果好壞移動目標。新文獻若直接覆蓋主張，決定合作、比較或轉向；不要只在標題上新增形容詞。

### 之後每月

安排短時間更新最接近的 5–10 篇工作及作者 repo。新模型可用時，同時檢查 target 變強與 auditor 變強，兩者對題目影響不同。這是建議例行工作，尚未建立自動排程。

不必等一年才開始寫：一旦有可信結果，就寫問題定義、比較表與限制。若實證顯示原假設不成立，保留能重用的資料、程式和推翻理由，下一題從已累積的知識接續。
