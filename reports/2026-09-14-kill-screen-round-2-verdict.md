# Reward-hacking 選題：第二輪 kill-screen 裁決

檢視日期：2026-09-14。用途：9/15 meeting 的選題決策與簡報修正。

裁決：目前不能稱原提案為「kill-screen 下最好的碩論題目」。原提案未通過定題門檻；修復評估仍保留為優先驗證的研究主線。新找到的近鄰實質削弱了原本的 novelty 論證，尤其是「換情境後修復排名改變」及「研究 benchmark 分數能否預測外部稽核」這兩點。

這份裁決取代前一份報告中過強的「條件式首選」解讀。這次完成的是原始文獻、附件、公開資源與實驗設計的檢驗；沒有重跑論文、訓練模型，或產生修復排序的新實驗結果。文獻搜尋能指出已有工作與可指認的缺口，不能證明所有現存或未來研究都不會重疊。

## 1. 現在到底是哪個判斷改變了？

### 原提案
> 研究 reward-hacking 修復成效的外推有效性；先證明現有評估會選錯修復方法，再研究如何用有限診斷證據避免這種錯判。

### 應作兩處修正：
1. **「先證明」改成「先檢驗」**：不能預先決定實驗必須發現錯判。
2. **「發現錯判 → 開發診斷選擇器」中間缺了一關**：現成的多情境評估、簡單選擇規則與同預算直接測試，是否已經足夠？如果足夠，就沒有理由繼續開發額外診斷系統。

| 判斷項 | 本次結論 | 證據狀態 |
| :--- | :--- | :--- |
| 老師的異常診斷／修復問題是否值得研究 | **是** | 附件直接提出；既有研究展示困難與有效介入 |
| detector 是否因為有 AuditBench 就不能做 | **否** | benchmark 與新 detector 不互斥 |
| detector 是否競爭密集、強 baseline 多 | **是**，對我們考慮的版本尤其如此 | TRACE、ARA、稽核方法與大型 prompted judge 已有實質能力 |
| 修復跨情境效果不同是否新 | **否** | 已有直接先例 |
| 修復方案跨情境排序改變是否新 | **不能當新主張** | ARA 的跨域防治表已有此結構 |
| 有限診斷能否改善未知機制上的修復選擇 | **尚未證實** | 既有低成本評估／模型選擇也構成近鄰 |
| 原提案是否比所有具體替代題更好 | **沒有足夠證據** | 缺資源實測及增量效益實驗 |
| 明天仍可主談什麼 | **修復評估的最小證偽實驗** | 研究投入建議，不是 novelty 認證 |

> **前次推論的錯誤**：把其他方向的寬泛描述拿去碰最強近鄰，卻替自己的候選保留較窄、更有利的描述；又把「還沒找到完全相同的研究」提升成「最值得押的題目」。即使每個限制描述都正確，這種不對稱比較仍不能推出排名。

## 2. 本次最重要的新近鄰

以下研究是對前次報告的實質補查，不把全部舊文獻重新列一次。引用的是作者頁或論文原文；預印本的結果按作者報告使用，不視為已獨立驗證。

### 2.1 ARA：連簡單的 A／B 排名交換都已有例子
ARA 先訓練 Hacker 與 Auditor，再由 Auditor 調整 RLHF 的獎勵。其 Table 5 比較不同訓練領域的防治方案。下表節錄兩欄，數字是論文報告的百分比，越低越好。[ARA, §3, §5.4.4](https://arxiv.org/html/2602.01750v1)

| 防治方案 | 迎合使用者的測試 (Sycophancy) | 程式作弊測試 (Code Hacking) |
| :--- | :---: | :---: |
| **A：在迎合類型上訓練** | 38.4% | 48.2% |
| **B：在程式作弊上訓練** | 54.8% | 19.6% |

在第一欄選 A，在第二欄選 B。這是從已報告表格讀出的排名交換，不能再把這種表格形狀本身當成我們的新發現。這裡改變的是同一框架的訓練領域；它不等於「同一個未知歷史的 hacked checkpoint，經兩種事後修復，且合法能力等價」的完整實驗，也不能從這張表獨立判斷排名差異的不確定性。

**對選題的含意**：把新題目的重點說成「A／B 會反轉」，已經不夠。換成事後修復或加能力對照可能有用，但須說明會改變什麼決策，不能只靠設定不同躲開近鄰。

### 2.2 Anthropic AAR：已研究修復搜尋與外部評估的關係
*Automated Researchers Can Mitigate Well-Characterized Alignment Failures* 已做自動對齊介入搜尋、多 benchmark 評分、能力檢查及外部稽核。Appendix D.1 顯示只優化單一 benchmark 的泛化問題；D.3 更直接檢查排行榜分數與 Petri 稽核結果的關係。D.3 只涵蓋兩類失敗、每類少數方案，作者明確不把高分區的差異解讀為已證實的平台期。[AAR, Appendix D.1–D.3](https://alignment.anthropic.com/2026/automated-alignment-researchers/)

因此，「第一次問安全評估能否指導修復選擇」不能成立。我們若要繼續，必須和現成的多情境選擇流程比較。不能只挑最弱的單一評估當對手，再說額外診斷有效。

### 2.3 HERALD：反事實診斷、最小修正與能力門檻也有近鄰
HERALD 對檢索代理的 reward program 作配對反事實稽核，找出需要修正的檢查條件，再評估訓練後策略的表現。它明確區分獎勵規則抗攻擊、實際行為發生率及能力保留；部分結果並未同時通過全部門檻。[HERALD, §4, §7–8](https://arxiv.org/html/2608.06012v1)

它修的是獎勵程式，與「已訓練模型的事後修復」不同；但「用對照診斷選修正、再檢驗行為與能力」的廣泛構想已不是空白。

### 2.4 AuditRepairBench：名字很近，但研究對象不同
此研究處理的是 coding agent 修復軟體時，評估器通道如何影響評分與排名，並用配對執行資料檢查。[AuditRepairBench](https://arxiv.org/html/2605.04624v1)

這不是修復 reward-hacked 模型的權重。不能看見 repair、audit、ranking 三個詞就判定完全撞題；同樣不能忽略它對「評估錯誤改變選擇」的一般方法重疊。

| 最近鄰 | 被修正／選擇的東西 | 與原提案的關係 |
| :--- | :--- | :--- |
| **ARA** | 防治訓練方案 | 已有跨域防治比較；不直接等於未知歷史模型的事後修復 |
| **AAR** | 對齊訓練介入 | 選方法與外部泛化高度相關，必須納入基線 |
| **HERALD** | reward program | 對照稽核到介入選擇的近鄰 |
| **AuditRepairBench** | coding agent 的軟體修復與評估通道 | 對象不同，不能當完全重複 |
| **我們的原提案** | hacked checkpoint 的修復選擇 | 精確增量仍待證明 |

## 3. 為什麼仍不直接改押 detector？

「detector 是紅海」只能作投入排序的理由，不能作邏輯上不可能研究的理由。比較要落到具體 detector。

1. **AuditBench** 是隱藏行為模型與稽核技術的評估平台，也包含 investigator。它提供研究新稽核方法的測試基礎，不是禁止後人做 detector。[AuditBench](https://arxiv.org/html/2602.22755v2)
2. 我們曾考慮「加對照脈絡，減少誤判正常程式操作」；但 **TRACE** 已將對比分析用於程式環境的 reward-hack detection。新方法至少要超越這個設計，而不是只超越看單條軌跡的簡單 judge。[TRACE: Contrastive Analysis](https://arxiv.org/abs/2601.20103)
3. Anthropic 的 lie-detector 研究提供另一個具體警訊：專門微調的偵測器在未見謊言類型上增益有限，而強大的 prompted model 已有很高表現。這支持將強 judge 放入 baseline；謊言偵測不等於全部 reward hacking，不能把其數值直接套到我們的任務。[Fine-Tuned Lie Detectors Failed to Generalize](https://alignment.anthropic.com/2026/lie-detectors/)
4. 另一個候選是提供更完整的主機事件、權限及評分來源資訊。然而 **BenchShield** 已研究評估基礎設施的獎勵完整性與相關證據。只把「更多 log 給 judge」當新方法，也可能重疊；仍需證明具體新增訊號的必要性。[BenchShield, §6, Appendix E](https://arxiv.org/html/2609.11028v1)

**對 detector 的固定判決**：保留競爭資格，但目前沒有一個已證實優於現成基線、且比修復評估更值得投入的具體方法。若低成本實測發現強 judge 與對比基線都穩定失敗，而一個便宜、可泛化的證據來源能修正，排名就應上升。單說「我還可以做 detector」不會改變排名；提供這種增量證據才會。

## 4. 所有候選用同一把尺比較

評估順序固定：① 與研究目標相連；② 與最近鄰有實質差異；③ 差異帶來決策或效能價值；④ 現有資源可做；⑤ 換強模型／簡單方法後仍有價值。缺少資料不以主觀分數補上，不用「8.7 分」假裝有精確排名。

| 具體候選 | 必須贏的對手 | 可能新增的價值 | 最大未過關處 | 本次定位 |
| :--- | :--- | :--- | :--- | :--- |
| **D1：權限／證據感知 detector**，在整類未見機制降低誤報 | 強 prompted judge、TRACE、完整證據的 judge | 同召回下較少誤報，或同品質更低成本 | 差異可能只是提供更多資訊；跨機制與跨模型增益未知 | 備選 pilot；未定題 |
| **D2：有限查詢下自適應模型稽核** | 固定題組、同預算 investigator、簡單多樣性選題 | 每單位成本發現更多獨立異常 | 容易只學到同一批植入模型／題型；query 數不等於成本 | 暫不優先做完整系統 |
| **R1：新的能力保留修復配方** | benign SFT／DPO、KL 保留、既有修復／自動搜尋 | 更好的能力—風險取捨，且能轉移 | 尚無具體機制假說；訓練成本高 | 不先承諾新演算法 |
| **P0：固定現成修復，檢驗多情境評估能否選好** | 多情境平均、最差情境、直接測試 | 判明是否存在值得研究的選擇缺口 | 可能完全沒有增量缺口 | **優先小實驗** |
| **P1：有限對照診斷改善修復選擇** | P0 全部基線、簡單回歸、固定最佳修復 | 未見機制選擇的風險／成本改善 | 需許多獨立模型與修復的結果作訓練標籤；價值未證實 | 原完整提案，黃燈 |
| **T1：歷史證據不可靠時的 router 修正** | LENS、RACER、簡單重校準／強模型 | 成本—品質改善或更可靠決策 | 舊 variance 想法可能無新資訊；真實漂移資料未核實 | 保留實驗室延伸備案 |

* **R1 的競爭密度有具體例子**：[IR³](https://arxiv.org/html/2602.19416v1) 已做配對策略的 reward reconstruction、特徵診斷與四類修復，並要求已知 hacking 範例；[A3](https://alignment.anthropic.com/2026/automated-alignment-agent/) 則將失敗分析與安全微調串成自動流程。兩者的範圍不同，足以反駁「做修復流程本身很新」，不足以證明所有新修復都沒機會。
* **T1 的直接近鄰也存在**：[LENS](https://proceedings.mlr.press/v337/liu26b.html) 明確處理互動回饋的可靠度；[RACER](https://arxiv.org/html/2603.06616v1) 處理路由風險校準及相關選擇。此處不聲稱已驗證 VDAR 的公式或把所有 drift 設定判死。

**為何仍先 P0？** 這是「下一筆小額研究投入」的選擇：它直接檢查老師問題中修復是否有效，且能同時回答「要不要新 selector」「哪個現有修復值得研究」「能力測量是否夠用」。它的失敗也能阻止投入更昂貴的 P1。這是資訊價值與題目銜接的判斷，不是 P1 已有最佳新穎性。若連可用 checkpoint、兩種權重修復與環境都拿不到，P0 的資源前提失敗，D1 的現成軌跡分析會更實際。

## 5. 原提案必須承受的反駁，逐條作答

| 反駁 | 是否成立 | 結果如何影響題目 |
| :--- | :--- | :--- |
| **「OOD 本來就會掉分」** | 成立，單純掉分不夠 | 要研究有成本或風險後果的選擇錯誤，並超越多情境基線 |
| **「A／B 換領域排名本來就會變」** | 已有先例 | 不能拿玩具 A／B 當 novelty 證據 |
| **「直接在目標情境測不就好？」** | 若測得到且成本合理，成立 | 必須加入同成本直接測試；輸了就停 P1 |
| **「拿更多來源類型一起測不就好？」** | 有力，必須實測 | 與平均、最差情境、留一領域驗證比較 |
| **「更好的修復全部都贏，就不用選」** | 成立 | 固定最佳方案是 baseline；若穩定支配，selector 沒價值 |
| **「少作弊只是能力變差」** | 可能 | 同構合法任務與拒答門檻；未過不稱有效修復 |
| **「只是在坑前面放得更明顯」** | 可能 | 固定機會、分開自然探索與端點選擇，不能混算 |
| **「你永遠說模型藏起來，怎麼輸？」** | 不能接受這種不可證偽說法 | outcome 是可觀察事件；沒事件只對指定測試給區間，不假定內心作弊 |
| **「更多診斷當然更好，預算呢？」** | 成立 | 計入 token、工具步驟、judge、人力標註與離線資料成本 |
| **「把一個模型的回覆切 train/test，算跨模型？」** | 不算 | checkpoint／訓練 lineage 和機制要在外層隔離 |
| **「只有特意挑的一對方法會翻」** | 不足以支持一般方法 | 預先固定候選，報全部比較，禁止事後挑一對 |
| **「新強模型出來後 detector／selector 沒用了」** | 真實可能 | 強 judge、較強目標模型與多樣修復都應測；不能保證未來 |
| **「把評分器鎖好就解決了」** | 在某些部署成立 | 系統防護作實用 baseline；若全面支配就降低模型修復投入 |
| **「這就是一般 domain generalization 的 model selection」** | 一般問題確實已知 | 需安全決策中特有的量測問題及實證價值；換名不夠 |

* [DomainBed](https://arxiv.org/abs/2007.01434) 已把模型選擇視為 domain generalization 的核心問題，並比較來源、留一領域及目標 oracle 等選擇方式。因此，一般模型選擇框架不是本題可宣稱的新概念。
* [tinyBenchmarks](https://arxiv.org/abs/2402.14992) 已展示用少量代表題估計大 benchmark 表現。它不解決任意未知作弊，但「少量題估分」本身不新；我們必須計入建立代表題所需的歷史資料成本。
* 另外，不要把「縮短推理，看作弊是否較早成功」當新點子：已有研究以截斷推理的效能曲線偵測 implicit reward hacking。[Is It Thinking or Cheating? (Wang et al., 2025)](https://arxiv.org/abs/2510.01367)。其 TRACE 縮寫與程式對比分析的 TRACE 是不同工作。

## 6. 還剩下哪個值得驗證的問題？

### 建議目前的工作標題：
> **具能力保留約束的 reward-hacking 修復選擇：多情境評估是否已經足夠？**

**白話**：我們有幾種讓模型少作弊的辦法。如果用幾種既有考試選出最好的一種，它到沒考過的作弊情境，是否真的比較可靠，而且還會正常做事？如果現成的選法已經夠好，就不用再發明新選法。

這是同一主線的檢驗問題，不是用加長標題掩飾 novelty。只有通過以下三個條件，才升級為原先 P1：
1. **有值得改善的錯選**：強多情境評估選出的方法，在未見機制有可重現、具實際影響的風險劣勢；不是抽樣噪音或普通能力降低。
2. **錯選能事前預測**：部署前可取得的對照訊號，對來源分數、一般能力、模型身分之外仍有增量；不是把目標答案偷放進 predictor。
3. **預測改善真實決策**：同總預算下，勝過直接稽核、簡單選擇及固定最佳修復；保留能力而非增加拒答。

任何一點沒過，都不能報告「有限診斷選修復的方法已成立」。如果只剩重現已知的泛化失效，作為閱讀／研究訓練可以有價值，不能自動升格可投稿貢獻。

### A／B 例子怎麼講才不會被問倒？
下面是假想數字，僅解釋研究問題，不是新結果：

| 方法 | 已測情境作弊率 | 未見機制作弊率 | 合法任務完成率 |
| :--- | :---: | :---: | :---: |
| **修復 A** | 5% | 30% | 90% |
| **修復 B** | 10% | 15% | 90% |

用已測情境會選 A；若真正要用的環境接近右欄，B 才較好。但是：
- 不知道未來環境偏向哪種，不能說 B「全域較好」。需要明確指定目標任務組合或最差情境目標。
- 我們不能用右欄挑選方法，再把右欄當未見測試。
- 兩個 90% 只是表格假設；實驗必須在足夠精度下驗證能力可接受。
- **真正候選貢獻不是這個例子，而是在不能看右欄全部答案時，是否能以合理成本選得更好。**

## 7. 最小、可以真正失敗的實驗規格 (P0)

### 7.1 對象先說清楚
* 主要對象是已經出現 reward-hacking 行為的公開模型 checkpoint。主張是改善已定義未授權行為的發生率；不宣稱讀出內心、不宣稱移除所有潛在目標。
* 至少比較 untreated 與兩種可重現的事後權重修復。一般反作弊 prompt 和工具權限限制另列系統介入，不能當成兩種權重修復充數。修復超參數必須給公平搜尋預算，否則比較的是調參用心程度。
* 介入起點都來自相同 hacked checkpoint；若宣稱跨模型適用，再增加獨立訓練的 lineage 與不同 base。多個 checkpoint 若只來自同一訓練歷程，不是多個獨立模型家庭。

### 7.2 任務與標籤
* 選擇可合法完成、有明確授權邊界、且能記錄特定 exploit 行為的環境。[HVE (Roth et al., 2026)](https://github.com/MajoRoth/hack-verifiable-environments) 的公開實作提供現成可核實機會，可作起點；其涵蓋的特定 hack 不等於所有作弊。
* 主要 split 是完整作弊機制／因果通道的留出；同一個答案檔案換路徑，不算新機制。先固定 tool harness、步數、規則及評分。不同機制仍須有合理共同任務結構，避免強行比較完全無關的能力。
* 每個任務分開記錄：合法完成、未授權嘗試、成功作弊、拒答／中止。對合法控制版本額外記錄相應工具操作能力。標籤不只由欲評估的 detector 自己提供；預先定義事件、抽查不警報軌跡，保留模糊標籤。
* **不能只篩出成功走到作弊機會的 runs 才分析**。修復可能本身改變到達率，這樣篩選會造成比較偏差。主要效果使用所有預先指派 runs；直接提供機會的端點測試是另一個、明確限定的估計量。

### 7.3 必須存在的基線
| 基線 | 選擇方式 | 它能否殺掉提案？ |
| :--- | :--- | :--- |
| **不修復** | 保留原模型 | 能；若修復只降能力或無增益 |
| **固定最佳修復** | 在開發資料選一個，全程使用 | 能；若沒有值得適應的差異 |
| **單一來源分數** | 按常用評估選 | 僅動機基線，贏它不夠 |
| **多情境平均** | 在相同來源預算分散測試 | 能；若已可可靠選擇 |
| **最差情境／下置信界** | 預先指定保守選法 | 能；若不需要額外訊號 |
| **留一來源領域驗證** | 用來源領域互相模擬外推 | 能；基本 OOD model-selection baseline |
| **同預算直接稽核** | 把診斷成本花在相關情境測試 | 能；也是最重要的實用對手 |
| **強 judge／現成 investigator** | 相同資訊與總預算 | 能；防止只贏弱 classifier |
| **簡單預測器** | 來源分數＋能力＋模型資訊 | 能；防止新架構只是擬合已知資訊 |
| **完整目標 oracle** | 看完整目標評估後才選 | 只能估計可改善空間，不是可部署對手 |

若目標測試真的不可取得，必須解釋原因，例如新機制尚未被發現，或昂貴環境建置。此時不用不存在的資料當部署 baseline，但還是要比較同成本、多樣的來源稽核；也不能宣稱對任意未來機制有保證。

### 7.4 衡量真正的選擇價值
* 先定義合法能力容忍損失 $\epsilon$，以及目標任務組合或 worst-case 目標。$\epsilon$ 是與老師／使用情境共同確定的設計選擇，不是文獻給定常數。
* 對目標環境族 $E$，令 $R_E(a)$ 是修復 $a$ 的未授權事件風險。可比較的方案集合包含不修復，以及符合能力門檻的方法。
* 選擇損失可寫成：
  $$\text{Regret} = \text{所選方法在 } E \text{ 的風險} - E \text{ 中符合能力門檻的最佳候選風險}$$
  白話就是「選錯這個修復，多承擔了多少風險」。在完整目標資料上估計這個量時，也要處理 oracle 選最小值造成的偏差；可用獨立評分子集或交叉評估，並報選擇不確定性。
* 不只報相關係數。平均分相關高，仍可能選錯最上面的兩種；相關低，也可能因為所有方法差不多而沒有實際選擇損失。主要結果是能力門檻、選擇損失和總成本。
* **能力保留不能用「差異不顯著」當證明**。應預先指定 $\epsilon$，檢查配對能力差的區間能否排除超過 $\epsilon$ 的損失。資料不足就標為證據不足，不能因區間很寬而通過。

### 7.5 分割與不確定性
* 修復訓練、selector 開發、最後評估分離；若要泛化到新修復家族，整個家族在外層留出。
* 任務模板與模型 lineage 是相關群組，不能把所有 rollouts 當獨立樣本。
* 固定測試預算與主要對比；適應性加測若使用一般固定樣本區間，必須另處理停止偏差。
* 多方法／多機制比較，要防止挑最漂亮的排名反轉。
* 小 pilot 用來看執行可靠度、事件頻率、群組變異與大效果；不以「沒有顯著差異」宣布題目不存在。
* 例如，在獨立同分布、固定樣本量、標籤無誤的二元測試中，$n$ 次都沒有事件，單側 95% 上界是 $1-0.05^{1/n}$。$n=100$ 時約 2.95%。這只約束該取樣分布，不約束沒測過的機制；同一模板重複 100 次也未必滿足獨立條件。這是數學示例，不是模型安全驗證。

## 8. 資源是否真的能做？

* 公開 [School of Reward Hacks 集合](https://huggingface.co/collections/thejaminator/school-of-reward-hacks) 可見 Qwen3-32B hacker 與 control 權重。本次核實集合可讀，沒有下載或驗證在實驗室能訓練；不能直接假設存在合用的 8B 配對版本。
* 32B 以每參數兩 bytes 儲存，單權重約 64GB；4-bit 的理想權重本體約 16GB，尚不含 metadata、KV cache、activation、optimizer 等。這是儲存量計算，不能推出單張卡一定能以指定長度訓練。用量化也要對能力與 hacking 行為重新校準。
* [AAR 官方程式](https://github.com/YuehHanChen/automated_alignment_researcher) 提供獨立評估入口，不一定要重跑完整自動研究流程；其 reward-hacking 軸使用小型模型及文本／遊戲類評估。這可減少流程建置，但不等於已備妥老師所問的未知歷史 hacked coding model。
* [Iterative DPO (2026)](https://arxiv.org/html/2609.06649v1) 的新研究提供另一個建立模型實驗體的線索；本次沒有確認符合我們設定的 checkpoint、授權與完整修復管線。不能把「論文能訓練」當成「我們下週就能直接使用」。
* **P1 比想像中貴的部分**：它不是只在一個模型問 100 題。為了學「診斷 → 哪種修復較好」，通常先要很多模型／修復組合的目標結果當標籤。線上省查詢，不代表整體研究省成本。這也是 P0 必須在 P1 之前的理由。

### 兩週安排與資源停止條件
| 階段 | 要拿到的結果 | 不成立時怎麼辦 |
| :--- | :--- | :--- |
| **第 1–2 天** | 確認權重、授權、環境、兩種修復實作；跑一小批合法與作弊機會 | 無可行權重修復或正常任務幾乎不會，停止原管線 |
| **第 3–5 天** | 在同一 checkpoint 重現兩種修復；確認指標與預算 | 若只有 prompt 可跑，改標系統防治 pilot，不能稱模型修復 |
| **第 6–9 天** | 固定機制 split，比單一來源與多情境基線；報全部候選 | 若資料不足，只估後續樣本需求，不宣稱 kill |
| **第 10–12 天** | 僅在有明確選擇缺口時加入少量對照特徵與簡單預測器 | 多情境／固定最佳已足夠，就停 P1 |
| **第 13–14 天** | 裁決：有價值缺口、沒有可見增量、或證據不足且成本超標 | 不因 sunk cost 增加神經網路或重命名題目 |

最低執行驗證可只用少量任務；真正的效應比較樣本量要依試跑估計、希望檢出的最小風險差與群組變異決定。不能預先承諾固定千餘條軌跡就能證明跨模型泛化。

本次尚不知道可用 GPU 時數、API 經費和老師對實證型論文的接受度。附件《研究生需知》第 11、15 頁要求大規模 API 與 H100 使用前說明／確認。明天要帶的是模型大小、修復數、episode 數、每回合 token／步數、試跑時間及成本估算欄位；不能把「實驗室有 H100」寫成資源已到位。

## 9. 跟老師四頁 PDF、routing、Anthropic 的連結

* **老師 9/12 PDF 第一頁問**：給定未知訓練歷史的模型，能否診斷異常 reward-seeking／reward-hacking tendency，並在不破壞正常能力下移除。這提供「診斷 → 介入 → 驗證」的研究問題。
* **本題接的是最後一段**：我們用什麼證據，判斷介入真的改善了行為而且保住能力？這是對老師問題的具體化；不是老師已經指定要做 selector。
* PDF 中「Can We Repair a Reward-Hacked Language Model?」可當討論問句。其連結的正式標題是 [Training a Misaligned Reward Seeker](https://alignment.anthropic.com/2026/reward-seeker/)，核心是建立與研究 reward-seeking 模型。該研究發現行為與評分情境密切相關；這支持評估情境需被檢查，不代表已提供通用修復法。
* **不要把幾個 Anthropic 工作混為一個「最新修復方法」**：
  * [2025 Natural Emergent Misalignment](https://arxiv.org/html/2511.18397v1) 比較多種防治；一般安全訓練有語境限制，針對性訓練與作弊懲罰在其設定更有效。Inoculation prompting 主要改變訓練行為的語意脈絡，以減少廣泛失準的遷移，不能等同完全移除已學會的作弊。
  * [2026 Reward Seeker](https://alignment.anthropic.com/2026/reward-seeker/) 是本次老師的模型行為 seed，不能把其他文章的方法歸到這篇。
  * [AAR (2026)](https://alignment.anthropic.com/2026/automated-alignment-researchers/) 是另一個自動找對齊介入與評估的研究流程，見第 2.2 節。
* **Routing 的歷史來源**是實驗室的信心估計、模型選擇、品質—成本問題；《Lab Intro》第 12、13、17 頁能支持。它不是 reward-hacking 修復的必要前提，也不是你的核心必然推論。兩者可共享「有限證據下做決策」的方法觀點，但簡報中應當成曾考慮的另一條支線，不要畫成 router 自然導出 hacking。

## 11. 哪些新資訊會真的改變裁決？

| 新資訊／結果 | 裁決變化 |
| :--- | :--- |
| 再指出 AuditBench 是 benchmark | 不變；已納入，detector 從未因此被邏輯排除 |
| 再指出「有人做修復」 | 不變；必須指出跟精確設定、方法和結果的重疊 |
| 找到已完成同設定、同能力控制、同預算選擇比較的研究 | 降級或停止 P1，除非已有實質增量證據 |
| 多情境基線／直接測試已達到可接受選擇品質 | 停 P1；不靠更複雜架構保住題目 |
| 修復 A 在所有合用設定穩定支配其餘方法 | 停自適應 selector，採固定方案 |
| 有穩定錯選，但少量訊號無法改善 | 只能考慮有廣度與解釋的實證研究，不自動保住方法題 |
| 有跨 lineage／機制、能力保留、同成本的增量改善 | P1 才升為強候選 |
| 沒有合用模型／訓練資源 | P0 不再是最實際下一步；轉 D1 的可執行試驗 |
| 更強模型或 judge 消除效果 | 對應方法價值下降；不宣稱「hacking 永存所以我永存」 |

穩定的結論應靠固定判準，而不是拒絕被證據推翻。目前最有根據的行動是做 P0 的小型基線檢驗；P1 的新穎性、樣本需求及決策價值仍未通過。這是本次深入檢驗後的具體裁決。
